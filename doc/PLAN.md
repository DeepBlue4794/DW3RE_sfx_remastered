# 原版戰場提示音還原 MOD 製作計劃

更新日期：2026-10-31

目標：先完成僅替換「我方將領敗走」的 PC 測試版，再逐項加入擊敗敵將與歡呼聲。最終以獨立、可移除的補丁交付。

## 對應與範圍

| 用途 | 原版來源 | 重製版匯出序號 | 音庫資料 ID（小端整數十六進位顯示） | 狀態 |
|---|---|---|---|---|
| 敗走 | linkdata_00007.wav | Sys09 | 3092803a | 使用者辨識，第一優先 |
| 擊敗敵將 | linkdata_00006.wav | Sys08 | 8d6fdd11 | 使用者暫定，後續遊戲內確認 |

Sys 序號是本次解碼器匯出順序，並非遊戲事件編號。第一版只改敗走；其餘 52 個音訊資料項目應維持原樣。若同一音訊被多個事件共用，必須在實測時記錄影響範圍。

## 階段與驗收

### 1. 保存基準與核對對應 — 已完成

- 保存已抽出的 Sys 資源、KTSR 音庫、三個原版 WAV 的工作副本。
- 建立 SHA-256 雜湊、音檔格式、目標資料區段與 ID 清單。
- 解析音庫頂層 114 個區段，其中有 53 個音訊資料項目。
- 通過原樣重組一致性、區段邊界、音庫長度及目標 ID 核對。
- 沒有備份整個遊戲；目前保存的是必要素材與資源。沒有修改遊戲安裝檔。

驗收結果見 baseline-report.json。這些檢查只證明已知音庫的拆分與重組正確，不代表已完成任意音訊編碼或遊戲載入驗證。

### 2. 建立可載入的最小封裝 — 下一步

- 檢查 retoc 與目前遊戲 IoStore 版本的相容性，確認必要的 package metadata 與依賴能保留。
- 先在工作資料夾封裝未修改的 Sys 資源，再用獨立讀取流程抽回，比對音庫與內容。
- 然後以既有、相容的遊戲音訊製作易辨識的暫時測試內容，驗證補丁覆蓋是否生效。
- 未修改的補丁就算遊戲能啟動，也不能單獨證明它已被載入；必須有可觀察的覆蓋證據。

驗收：容器可重新讀取；資源路徑與依賴正確；遊戲可啟動；可確認測試內容實際生效，並可移除恢復。

### 3. 解決原版 WAV 的編碼與嵌入

- 目前三個重製版目標都是 KA1A、48 kHz、四聲道。vgmstream 已證明可以解碼，尚未證明可反向編碼。
- 優先研究韓文語音補丁的實際音訊格式與作者公開工具／說明。只參考方法，不把其音訊內容納入本 MOD。
- 路線 A：找到可用 KA1A 編碼流程，保留既有格式。
- 路線 B：若 A 不可行，研究遊戲實際支援的其他 KTSL2 編碼；解碼器支援某格式，不等於這款遊戲支援。
- 替代編碼未驗證前，不把 WAV 直接寫入原壓縮資料區，也不只改副檔名。
- 保留原版檔作為母檔；必要時再重取樣。聲道配置、增益、樣本數和時長要逐項確定，不能盲目複製到四聲道。

驗收：替換後音庫可解碼、敗走聲完整且無爆音或截斷；其他音效不變。最終仍需遊戲內驗證。

### 4. 製作 v0.1 敗走單項測試版

- 僅以 linkdata_00007.wav 替換 Sys09。
- 更新實際需要的區段長度、位移、音訊參數與外層封裝資訊，保留事件識別及未修改資料。
- 輸出獨立補丁、來源與版本清單、安裝與移除說明。
- 任何寫入 F 槽遊戲資料夾的操作，都依當時工具所需的檔案權限處理；工作區可先完成建置。

驗收：重新抽取補丁後確認僅目標音訊及必要結構資訊改動；未修改音訊逐項比對。

### 5. 遊戲內測試與調整

- 由使用者在可重現敗走的關卡／存檔測試，確認觸發時機、音量、尾音、連續通知及聲道表現。
- 同時觸發擊敗、苦戰／本陣危急等通知，檢查共用音訊影響。
- 移除補丁後重啟，確認還原。
- 記錄遊戲版本與現有其他 MOD；尤其同樣替換 Sys 音庫的 MOD 可能衝突。

驗收：敗走正確播放原版聲音、無非預期副作用、可移除恢復。

### 6. 擴充 v0.2

- 成功後加入 Sys08 擊敗與 Sys11 歡呼，逐項測試。
- 提供「只改敗走」與「三種音效」兩個互斥版本，使用者擇一安裝。
- 保留對應清單，之後再擴充其他已辨識音效。

## v0.4 音量與後續建置規則

使用者確認 v0.3 可用，要求五個音效加 5 dB，並套用所有後續修改。後續建置須使用 work/mod-development/audio_settings.json 與 audio_processing.py；以原始 WAV 重建、加峰值限制，不可累加增益。最新參考建置程式 build_v04.py；不要再直接使用舊版固定 -0.5 dB 的建置腳本。其餘 48 音效已驗證不變。v0.4 尚待遊戲實測。


## 2026-11-01：v0.5 音量預設（取代 v0.4 規則）

使用者回報仍太小聲，五個音效改為相對 v0.3 的 +10 dB 輸入增益及平滑飽和處理；解碼後 RMS 相對 v0.4 約增加 4–5 dB，音色可能稍硬。後續沿用 audio_settings.json、audio_processing.py、adpcm_encoder_safe.py，參考 build_v05.py，每次從原始 WAV 重建，不累加前版增益。表格 dB 空白沿用此預設。其餘 48 個音效不變。v0.5 尚待遊戲實測。
